# 赛事详情页 · 第二版

本稿用于讨论页面布局与交互，不改动小程序和云端数据。

## 页面顺序

原生导航 → 赛事名称与状态 → 时间、地点 → 公告 → 与我有关的赛事卡片 → 内容分栏 → 底部操作。

- 普通用户：我的车组、报名状态、我的成绩快捷入口。
- 工作人员：保留个人参赛入口，并增加本场任务入口，标明授权赛段和有效期。
- 管理员：保留个人参赛入口，并增加报名审核、成绩复核与发布入口。
- 最高管理员：增加本场人员授权入口；调整范围是当前赛事。
- 普通内容共用“介绍 / 报名 / 成绩”；授权角色才增加工作台或赛事管理分栏。
- 已完赛时现场录入关闭，历史记录可查，普通用户主按钮为查看成绩。赛中可演示授权录入、审核和发布。

## 视觉方案

沿用赛事橙 #F39800，正文墨色 #18232C，纸白 #FFFFFF，页面底色 #F3F5F7，操作蓝 #2463B5，成功绿 #237454。
中文使用 Microsoft YaHei / PingFang SC；车号与时间用 Bahnschrift / Consolas 等宽数字。
赛事标题 20px，模块标题 17px，正文 14px，辅助文字 12px。手机内容边距 18px，按钮高度至少 44px。
主要视觉特征是一张车组计时单：车号、阶段、累计成绩和发布状态对齐展示。避免把所有内容都放进相同的圆角卡片。

## 与原详情的区别

报名组别移入报名分栏，避免十多个组别占满第一屏；介绍、完整规程和联系信息仍有直接入口。
点赞、评论、分享归入底部操作条，避免遮挡正文、录入框和表格。本稿的社交按钮只作交互演示。
当前赛事是已有的嵖岈山活动，原活动已完赛。设计稿提供“赛中演示 / 已完赛”预览；人物、车号、赛段、成绩、人数、授权时间均为模拟数据，不代表真实赛事记录。SS1–SS9 用于演示已讨论的拉力赛功能，不代表该活动实际规程。

## 交互边界

身份与阶段切换位于手机画面外，仅供设计评审。生产界面由服务端权限决定。
普通用户只读已发布成绩；工作人员只在获授权赛段录入；管理员可以复核并发布；只有最高管理员调整授权。
原型的提交、发布、撤回授权等只更新当前页面内存；刷新即恢复，不发送任何业务请求。
真实实现需后端复核权限、有效期、阶段状态，建立变更日志和成绩版本；原型不替代这些后端控制。
